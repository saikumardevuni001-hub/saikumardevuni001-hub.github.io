Cybersecurity & cloud security learning roadmap

A structured path from first principles to cloud security, for students, career changers and anyone who wants to protect their own accounts and devices.

What this is: a roadmap of topics, practice tasks and trusted free resources. It is not a video course. Practise only on systems you own or have written permission to test. External platforms may offer optional paid features.

Syllabus

16 modules

Work through them in order. Open a module to see what to learn and a practice task to complete before moving on.

1. Cybersecurity fundamentals
  • Confidentiality, integrity and availability (CIA).
  • Assets, threats, vulnerabilities, likelihood, impact and risk.
  • Preventive, detective and corrective controls; defence in depth.
  • Policies, data classification and basic threat modelling.

Practice: list five everyday assets, name a threat and vulnerability for each, then suggest one preventive and one detective control.

2. Networking foundations
  • OSI and TCP/IP models, IP addressing, subnetting concepts and routing.
  • TCP vs UDP, ports, DNS, DHCP, ARP, ICMP, HTTP and HTTPS.
  • Switches, routers, VLANs, NAT, firewalls, proxies and VPNs.
  • TLS, secure Wi-Fi, segmentation and zero trust basics.

Practice: draw a small office network with a router, switch, firewall and two VLANs, and label the path of one web request.

3. Operating systems and endpoint security
  • Windows and Linux users, groups, permissions and services.
  • Patching, secure configuration, host firewalls and endpoint protection.
  • Windows Event Logs, Sysmon basics and Linux audit logs.
  • Disk encryption, backups and safe virtual-machine labs.

Practice: on your own computer or a VM, record update status, firewall status and one useful log location.

4. Identity and access management
  • Authentication vs authorisation; passwords, password managers, MFA and passkeys.
  • Least privilege, RBAC, privileged access and access reviews.
  • Active Directory and Group Policy basics.
  • SSO, SAML, OAuth 2.0 and OpenID Connect.

Practice: build a role-to-permission matrix for three job roles and mark where MFA and access reviews apply.

5. Cryptography and data protection
  • Encoding vs encryption vs hashing; symmetric and asymmetric encryption.
  • Salting, digital signatures, certificates and PKI.
  • Data at rest, in transit and in use; TLS.
  • Key rotation, secrets management and common implementation mistakes.

Practice: compare a password hash, an encrypted file and a signed document, and state what each does and does not provide.

6. Vulnerability management
  • Asset discovery, scanning and authenticated assessment.
  • CVE and CVSS, false positives, prioritisation and remediation tracking.
  • Scope, written authorisation and rules of engagement.
  • Report writing: evidence, impact, severity and fix.

Practice: using a sample report or lab, rank three findings by exposure and impact and write one clear remediation.

7. Web and application security
  • How browsers, servers, APIs, cookies, sessions and databases interact.
  • OWASP Top 10: broken access control, injection, cryptographic failures, misconfiguration.
  • Input validation, output encoding and secure session handling.
  • Secure SDLC, code review and dependency checks.

Practice: in an authorised training lab, inspect one request and identify where validation or access control is needed.

8. Security operations and SIEM
  • Log sources, timestamps, normalisation and retention.
  • SIEM alert rules, dashboards, correlation and triage.
  • Indicators of compromise and threat intelligence basics.
  • Incident lifecycle: prepare, identify, contain, eradicate, recover, learn.

Practice: review sample authentication logs, identify user, source, time and pattern, then write a short incident note.

9. Threats, malware and defence
  • Trojans, worms, ransomware, spyware and botnets.
  • Phishing, credential theft, brute force and denial of service.
  • Endpoint, email, DNS and network controls; MITRE ATT&CK.
  • Backups, recovery testing, business continuity and disaster recovery.

Practice: analyse a sample phishing email, list its warning signs and write a defence checklist.

10. Cloud computing foundations
  • IaaS, PaaS, SaaS; public, private and hybrid models.
  • Regions, availability zones and the shared responsibility model.
  • Virtual networks, subnets, routing and security groups.
  • Compute, object storage, databases, serverless and containers.

Practice: map a simple web app to cloud compute, network, storage and database, and mark provider vs customer security tasks.

11. AWS security fundamentals
  • IAM users, groups, roles, policies, MFA and least privilege.
  • VPC, subnets, route tables, security groups and NACLs.
  • EC2 hardening; S3 Block Public Access, bucket policies and encryption.
  • CloudTrail, CloudWatch, Config, GuardDuty and KMS concepts.

Practice: in a sandbox account, set up MFA, a least-privilege role, a private S3 bucket and audit logging.

12. Microsoft Azure security fundamentals
  • Subscriptions, resource groups and Azure Resource Manager.
  • Microsoft Entra ID, RBAC, MFA and Conditional Access.
  • VNets, NSGs, Azure Firewall and private endpoints.
  • Key Vault, Defender for Cloud, Azure Monitor and Azure Policy.

Practice: sketch a secure Azure setup with an Entra ID admin, RBAC, a private subnet, an NSG and Key Vault.

13. Cloud security architecture
  • Zero trust, identity-first security and secure landing zones.
  • Segmentation, private connectivity and controlled egress.
  • Encryption, key ownership and certificate lifecycle.
  • Central logging, posture management, resilience and isolated backups.

Practice: draw a cloud architecture showing identity boundaries, private workloads, central logs and backup isolation.

14. Governance, risk and compliance
  • Policies, standards, procedures and control objectives.
  • NIST CSF, ISO/IEC 27001 and CIS Controls overview.
  • Risk registers, audits, evidence and vendor risk.
  • Privacy, data retention, breach notification and continuity planning.

Practice: create a mini risk register with three risks, likelihood, impact, owner, treatment and review date.

15. Practical labs and portfolio projects
  • Build a home lab with VMs and intentionally vulnerable training targets.
  • Practise packet analysis with Wireshark on sample traffic.
  • Review sample logs and write a basic incident report.
  • Document scope, steps, findings and fixes, with no secrets in screenshots.

Practice: complete one small authorised lab and publish a concise write-up on GitHub.

16. Career readiness and continuous learning
  • Build a focused portfolio with clear project write-ups.
  • Practise explaining a security issue, its business impact and the fix.
  • Learn ticket handling, documentation and escalation.
  • Stay current through vendor advisories and official documentation.

Practice: prepare a one-page case study: problem, investigation, evidence, action, result, lesson.

Public awareness

Stay safe: how attackers trick people

Most attacks rely on urgency, trust, fear or curiosity, not advanced technology. Pause, then verify through a separate trusted channel.

Phishing emails and fake links

Messages imitate banks, couriers, employers or government. Check the full sender address and the real domain. Open the official site or app yourself instead of clicking.

Smishing and messaging scams

SMS, WhatsApp and Telegram messages claim a parcel is held or an account will be blocked. Don't use the link or number in the message; verify independently.

Vishing and impersonation calls

Callers pose as bank staff, police, tech support or your boss. Never share passwords, PINs, CVVs or OTPs. Hang up and call a number you trust.

Social engineering and urgency

"Act now", "keep this secret" and "you'll lose access" are pressure tactics. Slow down and confirm unusual requests with the person through another channel.

OTP and MFA fatigue

Never share an OTP or approve a sign-in you didn't start. Repeated prompts can be an attack. Deny them, change your password from the official site and report it.

Password reuse

One breached site exposes every account sharing that password. Use a unique password per service, a reputable password manager, and MFA or passkeys.

Malicious attachments and downloads

Unexpected invoices, job offers, APK files, cracked software and macro-enabled documents can carry malware. Install only from official sources.

QR-code scams

A QR code can hide a fake site or payment destination. Preview the address, check the domain, and don't enter credentials because a QR code asked.

Fake websites, apps and pop-ups

Lookalike domains and alarming pop-ups push you to pay or give remote access. Use official app stores and never allow remote control to an unsolicited caller.

Public Wi-Fi and rogue hotspots

Fake hotspots copy real network names. Confirm the name with the venue, avoid banking on unknown networks, and turn off auto-join.

SIM-swap

A criminal moves your number to their SIM to intercept calls and SMS. Set a carrier PIN or port-out lock, and contact your carrier at once if service suddenly stops.

Deepfake voice and video

AI can imitate relatives, managers or public figures. Verify urgent money requests on a known number, and agree a verification phrase with family or your team.

Payment and email-compromise fraud

Attackers impersonate suppliers or managers and ask for new bank details. Confirm changes through a previously verified contact and use dual approval.

USB baiting

A found USB drive or unknown charger may be malicious. Don't plug it in; hand it to IT or security.

Ransomware and extortion

Malware encrypts or steals files and demands payment. Keep protected or offline backups, patch systems, and report suspected ransomware immediately.

Cloud and data exposure

Public storage, excessive permissions, leaked API keys and open backups expose data. Use least privilege, private-by-default storage, MFA, secrets management and audit logs.

Before you click, pay, share or approve: STOP

  1. Stop. Don't react to urgency, threats or unexpected rewards.
  2. Think. Was this expected? Is it asking for money, credentials, an OTP or remote access?
  3. Verify. Use a trusted number, saved contact or official app, not the details in the message.
  4. Protect and report. Block the sender, keep evidence, and tell your bank, provider or IT/security team.

If you clicked a suspicious link or shared information

  • Stop interacting. Don't enter more information or approve prompts.
  • From a trusted device, change the affected password and any reused ones; sign out other sessions.
  • Contact your bank immediately if card, UPI or banking details may be exposed.
  • If you opened a file or installed software, run a security scan and tell your IT/security team.
  • Keep the message, sender details, transaction references and screenshots as evidence. Don't forward malicious links.
  • In India, report cyber financial fraud on the helpline 1930 and at cybercrime.gov.in ↗.

General awareness education only, not legal, financial or incident-response advice. For workplace incidents, follow your organisation's policy and contact its IT/security team.
